# Code review against the methodology (2026-10-15)

Reviewed: `run.py`, `positions.py`, `lrg/` at commit `7284f69` plus working-tree changes, against the run of 2026-10-13. A static review with synthetic tests; Sui endpoints were not reachable from the review environment, so anything marked *check* needs `agent/scratch/diagnostics.py` run from your machine.

## Verdict

The maths is sound: CLMM tick walking, Aftermath and DeepBook execution, route composition, split allocation, the exact cost budget, the seized factor, the health factor (E-Mode LT included) and the shocked-price weights all match their equations. Five problems change the headline numbers, and they push in both directions. Two understate capacity (missing venues, Turbos reads), one overstates it (grid interpolation), and two have unknown direction (token order, treasury share). Re-run after fixing them before quoting SUI → USDC or MBTC.

## B. Differs from the stated method

| # | Where | What | Fix |

| B1 | `run.py:579-591` | Stress splits debt across collaterals by value (`t·P`), not borrowing power (`t·P·LT`). The docstring says "by value", so code and docstring agree, but the methodology says borrowing power. | Multiply `cval` by the collateral's LT (E-Mode LT for E-Mode positions). |
| B2 | `run.py:639-652` | `unverified` only checks the winning path. A pair whose only route died from a failed read gets capacity 0 and `unverified = false`; a better path removed by a failed read is not flagged. ## D. Small

DeepBook book not sorted before walking (`venues.py:227`); DeepBook `size_for_slippage` counts the fee; Cetus negative-tick fallback in `_index_from_name`; β missing from stress Q; unpriced assets get price 0 in stress (hides liquidations); capacity saturates at $50M without a flag outside `adequacy.csv`.

## Verified correct (with tests)

- CLMM single range in both directions, multi-range tick crossing, full range vs x·y=k (rel. error ≤ 1e-14); fee on input; two's-complement decoding.
- Aftermath weighted invariant; DeepBook walk on a sorted book.
- Route composition passes each leg's output into the next; split allocation is ≥ best single pool and ≤ sum of independent outputs.
- Exact budget `1 − (1+φ)/(1+0.9·LB)`: 4.22 / 6.63 / 8.17 / 11.82% at LB 5 / 8 / 10 / 15%.
- Close factor read from chain: 0.35, uniform across reserves.
- Q*, Q_cap, Q_now and stress use Navi oracle prices (per-entry decimals), not pool-derived prices.
- Health factor matches Navi's own to 1e-9; E-Mode LT applied; shocked prices used in weights and on debt.
- Pairs with no priced path get capacity 0 and stay in the matrix.

## MBTC

Not a read failure. MBTC has one pool (Momentum MBTC/wBTC, $593k TVL, zero 24h volume), it read fine, and every MBTC route crosses it. Capacity is now priced against Navi's oracle, which prices MBTC and wBTC off one BTC feed. If the pool trades away from 1:1, or holds liquidity on one side only, the first $50 already costs more than the budget. The earlier ~$800k on a $593k pool was likely the artifact (C4). D4 shows which. If D4 confirms it, MBTC's only on-chain exit doesn't trade at the oracle price, which is itself a finding.
